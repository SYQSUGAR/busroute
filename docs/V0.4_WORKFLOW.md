# v0.4 任务式工作流建设说明

v0.4 的重点不是增加更多公交指标，而是把已有采集、SQLite、GIS 和导出能力改造成可追溯、可恢复、不会因按钮顺序产生不同结果的任务式工作流。

## 1. 项目层

每个 SQLite 数据库旁自动创建：

```text
<database_stem>_project/
├─ project.json
├─ logs/
├─ exports/
├─ gis/
└─ backups/
```

旧版 v0.3 数据库可直接打开，不移动原数据库。

`project.json` 记录：项目名、城市、数据源、数据库路径、任务状态、完整/部分数据状态、合并半径、最后一次运行、成果登记等。

## 2. 任务状态

任务状态统一为：

```text
NEW
READY
DISCOVERING
CRAWLING
PAUSING
PAUSED
POSTPROCESSING
COMPLETED
PARTIAL
FAILED
```

采集中锁定数据源、城市、扫描方式、合并半径和输出目录，避免界面参数与后台任务参数不一致。

## 3. 当前项目统一

主采集页和 GIS 页共用同一个当前数据库上下文。

从 GIS 页打开另一个 SQLite 时，会同步切换整个应用的当前项目，不再出现“主页面是榆林、GIS 页面是汉中”的情况。

软件会记录最近打开的数据库，下次启动自动恢复当前项目上下文。

## 4. 站点派生数据依赖

站点合并不再依赖“先点导出”才能更新。

程序为站点合并记录：

- 原始数据签名
- 合并半径
- 合并站点数量

当原始线路/站点发生变化，或用户把 120m 改成 80m 时，站点状态会显示“需更新”。

执行导出或 GIS 分析前统一检查依赖；如过期，先明确询问用户是否重新整理站点。

## 5. 部分数据保护

采集未完成时仍允许用户导出或分析当前快照，但必须明确提示“当前为部分数据”，避免把未完成结果误当正式成果。

采集运行中禁止直接执行正式 GIS 分析。

## 6. TransBigData 断点增强

线路发现任务改为细粒度保存：

- 宽泛搜索按 `seed + page` 记录
- 精确线路关键词记录重试次数
- 失败任务最多自动重试 3 次
- TransBigData 批次失败时自动二分拆批，尽量隔离单条异常线路

多次失败仍无法完成的任务标记 `failed_final`，数据库保持 partial 状态，不再错误标记为完整采集。

## 7. 安全退出

采集运行中关闭软件时，弹出“安全停止并退出”。程序停止提交新请求并等待当前请求结束；若 20 秒内仍未安全结束，则取消退出，避免强关造成状态不一致。

## 8. 持久日志与成果登记

每次任务自动生成独立日志文件，并在 `project.json` 登记最后一次任务。

导出的 CSV / Excel / GIS / 覆盖分析成果会登记：

- 成果类型
- 文件路径
- 生成时间
- 关键参数
- 数据源签名

## 9. 后续 v0.5

v0.4 先完成任务闭环。后续继续建设：

- 完整数据版本号与 dirty 依赖传播
- 成果历史版本管理
- 项目级 CRS / CGCS2000 管理
- 数据质量检查
- 站点人工合并/拆分
- GIS 分析工具箱扩展
